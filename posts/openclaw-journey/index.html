The Agentic Journey: Building a Secure, Automated AI Partner with OpenClaw

March 27, 2026 · 4 min · Teerakarna

The world of AI is shifting from chatbots that talk to agents that do. Over the last few months, I’ve been on a journey to build a “24/7 Jarvis” that lives on my local hardware. This post isn’t just about a tool; it’s about navigating the tension between total autonomy and personal security.

What is OpenClaw? (The Vital Stats)#

Before diving into the setup, we need to talk about “Molty” (the lobster).

  • Who: Created by Peter Steinberger (founder of PSPDFKit), OpenClaw went viral in late 2025, amassing over 337,000 GitHub stars.
  • What: It is an open-source autonomous AI agent framework. Unlike a standard chatbot, OpenClaw is an orchestration layer that gives LLMs a “body”—the ability to execute terminal commands, manage files, and control browsers.
  • Why: It provides a privacy-focused, model-agnostic “Jarvis” experience. It maintains persistent memory in simple Markdown files and proactively reaches out via messaging apps to report on tasks.

The NemoClaw Alternative#

In early 2026, NVIDIA introduced NemoClaw—a security-hardened wrapper for enterprise users. While NemoClaw offers strict “policy-as-code” guardrails, it often favors the NVIDIA ecosystem.

I chose OpenClaw because it is truly model-agnostic. I want the freedom to swap between Claude 3.5 Opus for reasoning, Llama 3 via Ollama for privacy, or specialized research models without corporate gatekeeping. However, this freedom introduces significant security risks—which is why I’ve treated this project as a DevOps engineering challenge.

Security & Sandboxing: Hardening the Lobster on macOS#

Running an agent with system-level access on your primary MacBook is a “lethal trifecta” of risk: unrestricted privileges, indirect prompt injection, and potentially malicious community skills. To mitigate this, I’ve adopted a layered defense:

1. Primary Sandboxing (The “Cage”)#

  • Docker/Podman Containerization: I run OpenClaw in an isolated container. The agent can only read/write to a designated workspace folder (e.g., ~/ai-workspace).
  • Virtual Machines: For zero-risk experiments, I use UTM to run OpenClaw inside a separate macOS VM with snapshot capabilities.

2. Essential Hardening Measures#

  • No “Crown Jewels”: OpenClaw is strictly forbidden from touching ~/.ssh or ~/Library/Keychains.
  • Network Monitoring: I use Little Snitch to monitor and block unexpected outbound connections.
  • Gateway Auth: I never run the gateway in none mode; gateway.auth.mode is always set to token.

Connectivity: Why Discord is My OS of Choice#

OpenClaw supports Telegram, WhatsApp, and Slack, but I settled on Discord for my primary interface.

  • Multi-Agent Parallelism: I use different channels (#research, #devops) to keep task contexts separate.
  • Human-in-the-Loop: Discord’s role-based system allows me to create an #admin-commands channel for high-risk tasks while keeping general tasks in public threads.
  • Rich Interaction: Reactions and threads make the agent feel like a teammate, not just a bot.

Secure Remote Access with Tailscale#

To talk to my agent from my phone without poking holes in my home firewall, I use Tailscale.

Tailscale creates a secure, encrypted “overlay” network (using WireGuard) that is free for personal use (up to 100 devices). My MacBook and iPhone act like they are on the same local Wi-Fi, even when I’m miles away. By binding the OpenClaw gateway to the Tailscale IP, I’ve created a “Private Island” for my AI—blocked from the public web, but always one tap away.

The DevOps Approach: Automating with Ansible#

As an engineer, I don’t believe in manual configuration. I want a reproducible “Source of Truth.” I’ve constructed a fully automated pipeline using Ansible to deploy OpenClaw on a rootless Podman-enabled Kind cluster.

This automated approach replaces ~8 hours of manual hardening with a 15-minute deployment:

  1. OS Hardening: Automates macOS/Linux security settings.
  2. Rootless Podman: Ensures container escapes only grant user-level access.
  3. Network Isolation: Configures Squid for egress filtering and ufw to block everything but Tailscale.
  4. Secrets Management: Discord and Tailscale keys are piped in via secure variables, never stored in plaintext on disk.

Resources & Further Reading#

If you’re looking to start your own journey with OpenClaw, here are the core tools I recommend:

  • Core Project: OpenClaw GitHub
  • Automation: Next-Kick’s Hardened Ansible Playbook
  • Networking: Tailscale Personal Plan
  • Mac Sandboxing: UTM (Free Virtualization)
  • Monitoring: LuLu (Open Source Firewall)

This is a journey of discovery. By treating my AI agent as a production service rather than a toy, I’ve built a partner that is powerful, unconstrained, and—most importantly—secure.
